# GoLB V1 Design Spec

**Date:** 2026-03-30
**Version:** V1 — Production Core
**Prerequisite:** MVP (v1.0.0) complete
**Goal:** Configurable, multi-algorithm, operationally manageable load balancer.

---

## Scope

| Feature | Included |
|---------|----------|
| YAML config file + CLI flag override | ✅ |
| Least-connections algorithm | ✅ |
| Weighted round-robin algorithm | ✅ |
| Admin REST API (no auth) | ✅ |
| Health check thresholds | ✅ |
| Connection draining (dual-server shutdown) | ✅ |
| Hot reload via SIGHUP | ❌ deferred to V2 |

---

## Architecture

### New packages

```
internal/config/    YAML parsing + CLI flag merge → Config struct
internal/algo/      Algorithm interface + RoundRobin, LeastConnections, WeightedRoundRobin
internal/admin/     Admin HTTP server + REST handlers
```

### Modified packages

```
internal/backend/   + Weight int, activeConns int64, IncrConns/DecrConns/ActiveConns
internal/pool/      + sync.RWMutex on backends slice, Remove(url), drop GetNextPeer()
internal/health/    + consecutive failure/success counters, unhealthy/healthy thresholds
internal/proxy/     LoadBalancer holds algo.Algorithm; tracks active conns per request
cmd/golb/main.go    uses config.Load(), wires algo + admin server, dual-server shutdown
```

## Section 1: Config (`internal/config`)

### Structs

```go
type Config struct {
    Server      ServerConfig
    Pool        PoolConfig
    HealthCheck HealthCheckConfig
    Admin       AdminConfig
}

type ServerConfig struct {
    Port int  // default 3030
}

type PoolConfig struct {
    Algorithm string          // "round_robin" | "least_connections" | "weighted_round_robin"
    Backends  []BackendConfig
}

type BackendConfig struct {
    URL    string
    Weight int  // default 1 if omitted
}

type HealthCheckConfig struct {
    Path               string        // default "/health"
    Interval           time.Duration // default 10s
    Timeout            time.Duration // default 2s
    UnhealthyThreshold int           // default 3
    HealthyThreshold   int           // default 2
}

type AdminConfig struct {
    Port int  // default 9090; 0 = admin server disabled
}
```

### YAML shape

```yaml
server:
  port: 3030

pool:
  algorithm: least_connections   # round_robin | least_connections | weighted_round_robin
  backends:
    - url: http://localhost:8081
      weight: 3
    - url: http://localhost:8082
      weight: 1

health_check:
  path: /health
  interval: 10s
  timeout: 2s
  unhealthy_threshold: 3
  healthy_threshold: 2

admin:
  port: 9090
```

### API

```go
// Load reads the YAML file at path (if non-empty), then applies CLI overrides.
// CLI values only override when explicitly set (non-zero / non-empty).
func Load(path string, args []string) (Config, error)

// Defaults returns a Config with all default values pre-filled.
func Defaults() Config
```

## Section 2: Algorithm abstraction (`internal/algo`)

### Interface

```go
type Algorithm interface {
    Next(backends []*backend.Backend) *backend.Backend
    Name() string
}

// New returns the named algorithm or an error for unknown names.
func New(name string) (Algorithm, error)
```

### Implementations

**RoundRobin** — wraps the atomic counter currently in `ServerPool`.

**LeastConnections** — iterates all alive backends, picks the one with the lowest `ActiveConns()`. Breaks ties by order of registration.

**WeightedRoundRobin** — smooth weighted round-robin (Nginx algorithm): each backend has a `current_weight` that increases by its weight each round; the backend with the highest `current_weight` is selected and has the total weight subtracted from its `current_weight`. Backends with `Weight <= 0` are treated as `Weight = 1`.

### Backend changes

```go
// internal/backend/backend.go additions
Weight      int    // set from config; default 1
activeConns int64  // managed atomically by LoadBalancer

func (b *Backend) IncrConns()
func (b *Backend) DecrConns()
func (b *Backend) ActiveConns() int64
```

### LoadBalancer connection tracking

```go
func (lb *LoadBalancer) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    peer := lb.algo.Next(lb.pool.Backends())
    peer.IncrConns()
    defer peer.DecrConns()
    // ... proxy as before
}
```

Every `ServeHTTP` invocation — including recursive calls for backend switches — calls `IncrConns` on the selected peer and defers `DecrConns`. Each peer tracks only its own active connections, so the least-connections algorithm always sees accurate per-backend counts.

## Section 3: Health check thresholds (`internal/health`)

`HealthChecker` gains per-backend consecutive counters stored in a private map.

```go
type HealthChecker struct {
    // existing fields ...
    unhealthyThreshold int        // failures before marking dead (default 3)
    healthyThreshold   int        // successes before marking alive (default 2)
    mu                 sync.Mutex
    consecutive        map[string]int  // backend URL → consecutive same-direction count (+ve=successes, -ve=failures)
}
```

### State machine

- **Probe succeeds:**
  - If `consecutive[url] < 0`: reset to 0 (direction changed)
  - Increment `consecutive[url]`
  - If `consecutive[url] >= healthyThreshold` and backend is dead: mark alive, reset
- **Probe fails:**
  - If `consecutive[url] > 0`: reset to 0 (direction changed)
  - Decrement `consecutive[url]`
  - If `abs(consecutive[url]) >= unhealthyThreshold` and backend is alive: mark dead, reset

Log transitions only (same as MVP). Defaults: `unhealthyThreshold=3`, `healthyThreshold=2`.

## Section 4: Admin API (`internal/admin`)

### Server

```go
type Server struct {
    pool *pool.ServerPool
    lb   *proxy.LoadBalancer
}

func New(p *pool.ServerPool, lb *proxy.LoadBalancer) *Server
func (s *Server) Handler() http.Handler   // returns ServeMux; used in tests without a live port
func (s *Server) Start(ctx context.Context, addr string) error
```

### Endpoints

| Method | Path | Body / Response |
|--------|------|-----------------|
| `GET` | `/admin/backends` | JSON array of backend status |
| `POST` | `/admin/backends` | `{"url":"...","weight":1}` → adds + wires proxy |
| `DELETE` | `/admin/backends/{url}` | removes backend |
| `POST` | `/admin/backends/{url}/enable` | sets alive=true |
| `POST` | `/admin/backends/{url}/disable` | sets alive=false |

`{url}` is URL-encoded in the path. All responses are `application/json`. Errors: `{"error":"..."}` with appropriate HTTP status.

### Backend status response shape

```json
[
  {
    "url": "http://localhost:8081",
    "alive": true,
    "weight": 3,
    "active_conns": 2
  }
]
```

### Pool changes for admin

`ServerPool` needs a `Remove(rawURL string) bool` method and its `backends` slice protected by `sync.RWMutex` (reads during `Backends()`, writes during `AddBackend` / `Remove`).

## Section 5: Shutdown

On SIGTERM/SIGINT:

```
1. cancel() — signals health checker goroutine and admin server to stop
2. adminSrv.Shutdown(shutCtx)   — drain admin traffic first (no more pool changes)
3. mainSrv.Shutdown(shutCtx)    — drain LB traffic (in-flight requests complete)
```

Both shutdowns share a single 30s `context.WithTimeout`. Admin drains first so no backend mutations race with the main server winding down.
